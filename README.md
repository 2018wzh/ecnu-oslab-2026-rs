## 2. 实验核心目标

用 4KiB 页面管理空闲内存，实现 Sv39 页表，在每个 CPU 上启用内核页表后仍能正常打印。

### 3.1 第一阶段：物理内存

首先关注链接脚本。代码、只读数据、可写数据、BSS 和每核栈不能动态分配。只管理页对齐的 `kernel_end` 到 `DRAM_BASE + DRAM_SIZE`。

基本原理是 **4KiB 页面切分 + 空闲链表组织**。前 1024 页属于内核池，剩余为普通池。`REGIONS[0/1]` 记录起止地址、锁、空闲数与链头。空闲页开头存放 next，分配出去后整页归调用者。

`init` 只调用一次；`alloc(true)` 使用内核池，`false` 使用普通池。分配摘取页面、更新计数并清零，耗尽返回 `None`。释放检查对齐、归属和重复释放，再归还链表。共享操作必须持锁。

访问静态区域时使用原始指针，先获取锁再修改相应字段，避免为整个静态结构建立不受保护的可变引用。释放页面前须消除所有引用及映射，不能让借用跨越释放。

### 3.2 第二阶段：内核态虚拟内存

串口资源没有区别，内存却被细分成许多通过地址区分的页面。页表记录地址对应关系，MMU 自动翻译。

Sv39 的三级页表各有 512 项，索引各 9 位，页内偏移 12 位。PTE 记录物理页号与标志位；有效且 R/W/X 全零的项指向下一级表，叶项指向数据页。

按 `walk → map → unmap → init` 完成。`walk` 返回叶 PTE 的原始指针，按需分配中间表。`map` 要求 va/pa 对齐、长度非零，尾部不足一页向上覆盖；拒绝越界、溢出、重复映射及 W 无 R 的权限。叶项设置 A/D，不依赖硬件自动更新。失败返回 `Err(())`。

`unmap` 清除叶项；`free_pages=true` 只释放普通池数据页，不能用于设备或内核镜像。教师提供 `kvm::print` 查看页表；它要求遍历期间页表不被修改。

内核恒等映射：代码 RX、只读区 R、其余内存 RW、UART RW，不设置 U，不映射固件保留区。此时不加入中断控制器映射。

### 3.3 接入启动

在自己的主核初始化中，打印初始化后调用 `pmem::init()`、`kvm::init()`，再发布初始化完成。各核观察到结果后调用 `kvm::init_hart()`。`ROOT` 只由主核写入并通过启动同步发布；不要用新答案替换以前的启动或锁。

## 4. 测试

```bash
cargo xtask build --config riscv64-qemu-virt
cargo xtask run --config riscv64-qemu-virt
cargo xtask image --config riscv64-visionfive2
```

先做物理页测试，再打开分页：

1. 两核各申请 512 个内核页，写不同内容，双方完成后并行释放；检查对齐、归属和不重复。
2. 普通池分配 10 页，写 0xAA 后释放，再申请应全页为零；空闲数恢复。
3. 耗尽两池应返回 `None`，释放后可恢复；非法归还要明确报错。
4. 将页映射到 `0x8000`、`0x100000`、跨二/三级索引位置及 `VA_MAX-PAGE_SIZE`，通过 `walk` 检查 PA 与权限。
5. 测试解除映射、重复映射、越界和未映射位置，对照修改前后的页表打印。
6. 两核启用分页后继续输出；对只读页写入应停在早期异常入口，可用 GDB 检查。

临时检查不保留在正常启动中。编译框架不代表运行测试已经完成。
